The Functional "Visitor Pattern"
To bundle operations onto one type and make adding new types easy in a functional language, you must abandon standard =>
Algebraic Data Types and pattern matching. Instead, you build mechanisms that couple state and behavior together:

The Scheme/Lisp approach (Message Passing): You create a constructor function that holds private state within a closure =>
and returns a secondary dispatcher function. This dispatcher takes a command (a "message" like 'area or 'perimeter) and =>
routes it to the correct internal calculation. You are manually building a vtable using closures.

The Haskell approach (Type Classes): You define a Type Class (an interface) grouping the required operations. When you =>
define a new data type, you instantiate the Type Class for it, completely encapsulating the type's specific behaviors in one =>
place without modifying existing functions.
